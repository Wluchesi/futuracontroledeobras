# DESENVOLVA UM SISTEMA WEB COMPLETO DE GESTÃO DE OBRAS

Quero que você atue simultaneamente como:

* Arquiteto de software
* Engenheiro de software sênior
* Especialista em UX/UI
* Especialista em gestão de obras
* Especialista em orçamento de construção civil
* Especialista em compras e suprimentos
* Especialista financeiro
* Especialista em bancos de dados
* Especialista em dashboards e BI

Sua missão é **projetar e desenvolver um aplicativo web completo para gerenciamento financeiro, orçamentário e operacional de uma obra**, baseado na estrutura descrita abaixo.

Não quero apenas uma demonstração visual ou protótipo. Quero uma aplicação funcional, com banco de dados, autenticação, CRUDs, relacionamentos, cálculos automáticos, filtros, dashboard e regras de negócio.

---

# 1. OBJETIVO DO SISTEMA

O sistema deverá permitir controlar uma obra desde o orçamento inicial até a execução financeira.

O fluxo principal deverá ser:

**CENTRO DE CUSTO**
→ **ORÇAMENTO**
→ **COTAÇÕES**
→ **ESCOLHA DO FORNECEDOR**
→ **CONTRATAÇÃO**
→ **COMPRA/LANÇAMENTO**
→ **CONTAS A PAGAR**
→ **PAGAMENTO**
→ **REALIZADO**
→ **COMPARAÇÃO ORÇADO x REALIZADO**
→ **DASHBOARD**

Todas essas informações precisam estar conectadas.

O usuário nunca deverá precisar cadastrar a mesma informação várias vezes.

---

# 2. PERFIL DO SISTEMA

O sistema deverá ser preparado inicialmente para pequenas e médias obras, mas a arquitetura deve permitir futuramente:

* múltiplas obras;
* múltiplos usuários;
* diferentes níveis de acesso;
* diferentes empresas;
* vários fornecedores;
* várias obras simultâneas.

Criar a estrutura pensando em SaaS desde o início.

Essa é uma das partes mais importantes do sistema.

Cada obra deverá possuir seu próprio orçamento executivo.

* Cotação 1

O sistema deverá calcular automaticamente:

**Menor Cotação = menor preço entre as três cotações**

**Total Contratado = Quantidade × Preço Contratado**

**Saldo = Total Contratado − Total Pago**

# 11. CONTAS A PAGAR

Criar módulo financeiro.

Cada lançamento deverá possuir:

* ID
* Obra
* Centro de custo
* Compra relacionada
* Fornecedor
* Documento
* Descrição
* Valor
* Data de emissão
* Data de vencimento
* Data de pagamento
* Forma de pagamento
* Conta bancária
* Status
* Observações

Status automáticos:

🟢 PAGO
🟡 A VENCER
🔴 VENCIDO

Regra:

Se possuir data de pagamento:
→ PAGO

Se não possuir pagamento e vencimento >= hoje:
→ A VENCER

Se não possuir pagamento e vencimento < hoje:
→ VENCIDO

Também calcular:

**Dias em atraso = Hoje − Data de Vencimento**

quando estiver vencido.

# 33. REGRA FINAL

Sempre que existir uma informação que possa ser derivada automaticamente de outra, NÃO peça ao usuário para digitá-la novamente.

Exemplo:

Se uma compra estiver vinculada ao orçamento ORC-0015, o sistema deve descobrir automaticamente:

* obra;
* centro de custo;
* etapa;
* item;
* fornecedor;
* orçamento;
* contratado;
* realizado;
* saldo.

O objetivo é que o usuário **lance a informação uma única vez e o sistema faça o restante automaticamente.**

Comece apresentando a arquitetura, banco de dados e fluxo do sistema. Depois implemente a FASE 1.
